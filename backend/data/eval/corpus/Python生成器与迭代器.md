# Python 生成器与迭代器

## 迭代协议

Python 的 for 循环背后是迭代协议：
- 对象实现 `__iter__()` 返回迭代器，迭代器实现 `__next__()` 返回下一个元素
- 没有更多元素时 `__next__` 抛出 `StopIteration`，for 循环捕获它并正常结束
- `iter()` 与 `next()` 内置函数是协议的直接入口

凡是实现了迭代协议的对象都能被 for 遍历：列表、字符串、字典、文件对象、`range`、自定义类都遵循同一套协议。

## 生成器：惰性产出的函数

生成器是"边计算边产出"的函数：
- 函数体中出现 `yield`，调用该函数返回的是**生成器对象**，函数体并不立即执行
- 每次调用生成器的 `__next__`（或 for 推进一次），函数从上次 `yield` 处恢复执行，产出一个值后再次挂起
- 函数自然结束或遇到 `return`，迭代抛出 `StopIteration`

```python
def read_lines(path):
    with open(path, encoding="utf-8") as f:
        for line in f:
            yield line.rstrip("\n")
```

与普通函数的核心区别：普通函数一次性算完所有结果再返回，生成器每步只算一个，调用状态保存在栈帧里。

## 生成器表达式与管道

`(x * x for x in data)` 是列表推导式的惰性版本——不生成完整列表，只在迭代时逐个计算。多个生成器可以串成管道：

```python
total = sum(int(line) for line in raw if line.strip())
```

优点是**内存占用恒定**：无论数据多大，同一时刻只保留一个元素，处理几个 G 的文本也不会把内存吃满。

## 生成器的进阶能力

- `yield from`：把一个子生成器的产出直接委托给外层，减少转发样板代码
- 生成器可带状态：同一生成器对象的多次推进互不干扰，可分别迭代
- `send()`：向挂起点回传值，实现简单的协程交互（`await` 的底层基础）
- 标准库 `itertools`（`chain`、`islice`、`groupby`）提供组合式迭代工具，全部基于同一协议

## 何时用生成器

- 数据规模未知或可能很大（日志、CSV、网络流）——先算完再处理会爆内存
- 只需要消费一次、不需要随机访问——列表的索引能力用不上
- 需要"用到才算"的惰性求值——配合 `sum`/`max`/短路判断可提前终止计算

反场景：需要多次遍历、需要 `len()` 或下标访问的数据，应保留为列表。
