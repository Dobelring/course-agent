# 数据结构：字符串与模式匹配

## 朴素匹配的问题

在文本 T 中查找模式 P，暴力做法逐个起点比对：最坏 O(n·m)（每次失配前已比对 m-1 个字符），失配时只把模式右移一位，重复劳动严重。

## KMP 算法

KMP 的核心：**利用已经比对过的信息**，失配时把模式右移到下一个"仍可能匹配"的位置，文本指针永不回退。

- 预处理"部分匹配表"（前缀函数 / next 数组）：`next[j]` 表示模式前缀 `P[0..j-1]` 中，最长的既是其前缀又是其后缀的长度
- 失配时模式右移量 = 已匹配长度 - 对应的 next 值；若 next 为 0 则整体右移一位
- 预处理 O(m)，匹配阶段 O(n+m)，总复杂度与文本长度线性相关

正确性关键：右移后新起点之前的文本位置必然不匹配（由 next 的最长性保证），因此不需要回头验证。

## 字符串哈希

把子串映射为整数哈希（多项式滚动哈希），比较两子串是否相等先比哈希值：
- 预处理前缀哈希后，任意子串哈希 O(1) 可算
- 配合进制与大素数取模降低冲突；双哈希可进一步压低误判概率
- 应用：判断重复子串、Rabin-Karp 模式匹配（期望 O(n+m)）

## Trie 前缀树

Trie 把字符串集合组织成一棵多叉树：从根到某结点的路径拼出一个前缀，终结标记表示完整单词。

- 插入与查找复杂度 O(单串长度 L)，与集合大小无关——适合前缀型查询
- 空间可能浪费（每个结点只存一条边的信息），可用双数组 Trie 或压缩路径优化
- 典型应用：前缀联想补全、敏感词过滤、单词接龙判存在性

## 编辑距离

把串 A 变成串 B 的最少操作数（插入/删除/替换各计 1）：
- `dp[i][j]` 表示 A 前 i 个字符变成 B 前 j 个字符的最小代价，转移取三种操作的最小值加一
- 复杂度 O(|A|·|B|)；常用于拼写纠错、近似去重、生物序列比对的简化版
